# Period Summary (Підсумки періоду)

## Зачем стандартизовано
Без скіла кожен раз AI вигадує свій формат. Один раз показує підсумки тільки доходів, інший — тільки витрати, третій — без порівняння з попереднім періодом. Юзер не отримує **передбачуваності**.

Цей скіл завжди дає однакову структуру → юзер швидше знаходить що треба.

## Воркфлоу

### Крок 1. Зрозуміти період
Розпарси з повідомлення:
- "за квітень" → 01.04–30.04 поточного року
- "за 1 квартал" → 01.01–31.03
- "за 2025" → весь рік
- "за останні 30 днів" → відносний період

Якщо неоднозначно — перепитай: "Який період? Місяць, квартал, рік?".

**Завжди визначай також "попередній період"** для порівняння:
- За квітень → порівняння з березнем (попередній місяць)
- За Q2 → порівняння з Q1 (попередній квартал)
- За 2026 → порівняння з 2025 (попередній рік)

### Крок 2. Витягнути дані за обидва періоди

```
mcp__finmap__get_operations({startDate: <p1>, endDate: <p2>}) // поточний
mcp__finmap__get_operations({startDate: <prev_p1>, endDate: <prev_p2>}) // попередній
```

Якщо обʼємно (>500 операцій на період) — додай фільтр по конкретному рахунку, якщо юзер уточнив.

### Крок 3. Обчислити основні метрики

**Для поточного періоду:**
- Загальний дохід (sum income)
- Загальні витрати (sum expense, без urgents — без перекладів між власними рахунками)
- Прибуток = дохід − витрати
- Кількість операцій (income / expense / усього)

**Топ-5 категорій витрат:** згрупуй expense по `categoryId/categoryName`, відсортуй за сумою спадно, візьми перші 5. Для решти — "Інші".

**Топ-5 контрагентів за оборотом:** згрупуй усі операції по `counterpartyId/counterpartyName`, обчисли сумарний |amount| (модуль), відсортуй спадно, візьми 5.

**Топ-3 проекти** (якщо у компанії є проекти): сума operations.amount по `projectId`.

### Крок 4. Порахувати дельти проти попереднього періоду

Для кожної ключової метрики:
```
delta_pct = (current − previous) / previous × 100
```

Якщо `previous` = 0, не показуй %, просто пиши "було 0".

Для напрямків: `+8%` зелене якщо це дохід, червоне якщо це витрата.

### Крок 5. Презентація — стандартний формат

```markdown
## 📊 Підсумок: {період} ({діапазон дат})

### Ключові метрики
| Метрика | {Поточний період} | {Попередній} | Зміна |
|---------|-------------------|--------------|-------|
| Дохід | **{X} грн** | {Y} грн | {+/−Z%} |
| Витрати | **{X} грн** | {Y} грн | {+/−Z%} |
| Прибуток | **{X} грн** | {Y} грн | {+/−Z%} |
| Операцій | {N} | {M} | — |

### Топ-5 категорій витрат
| Категорія | Сума | Частка |
|-----------|------|--------|
| {cat 1} | {X} | {%} |
| {cat 2} | {X} | {%} |
| {cat 3} | {X} | {%} |
| {cat 4} | {X} | {%} |
| {cat 5} | {X} | {%} |
| Інші | {X} | {%} |

### Топ-5 контрагентів за оборотом
| Контрагент | Оборот, грн |
|-------------|-------------|
| {x} | {X} |
| ... | ... |

### Висновок
{1-3 речення інтерпретації — що змінилось, на що звернути увагу. Не "ось факти", а "ось що ці факти означають".}
```

### Крок 6. Опційний візуал
Додай один графік (через `charts-output` skill):

- Якщо період = місяць → **bar** доходи/витрати по тижнях
- Якщо період = квартал → **bar** доходи/витрати по місяцях
- Якщо період = рік → **line** баланс по місяцях
- Або **pie** топ-5 категорій витрат

Один графік, не два. Інакше "стіна звітності" і втрата фокуса.

### Крок 7. Запропонуй дії
В кінці пропонуй:
- "Зробити такий же підсумок щомісяця автоматично?" → створення scheduled task
- "Бачу, що {категорія X} зросла на 40% — переглянути всі ці операції?"
- "Експортувати у файл?"
- Якщо є знакові аномалії: "Топ-витрата за період — {Y грн на категорію Z, на контрагента W}. Хочеш деталізацію?"

## Висновок — найважливіший рядок

**Не пропускай блок "Висновок".** Без нього звіт — суха таблиця. Приклад поганого висновку: "У квітні було 50 операцій". Приклад доброго:

> *"Витрати зросли на 18% переважно через зарплати (+30 000 порівняно з березнем — наймали нового співробітника). Доходи стабільні. Прибуток впав на 15% але це планове, бо новий найманий ще не дав віддачі."*

Якщо ти не маєш контексту звідки зміна — запитай юзера, щоб краще інтерпретувати наступного разу.

## Антипатерни

❌ **Звіт без порівняння з попереднім періодом** → юзер не розуміє чи це багато чи мало.

❌ **Топ-100 категорій** → нечитабельно. Топ-5 + "Інші".

❌ **Перекази між власними рахунками у "витратах"** → роздуває цифру вдвічі. Виключай transfer.

❌ **Прибуток для ФОП на ЄП** → на ЄП поняття "прибуток" не оподатковується. Можна пиратити, але натякни юзеру: "Прибуток показую для управлінської цілі — для податкової бази на ЄП це не релевантно".

❌ **Без блоку висновку** → зайво.
