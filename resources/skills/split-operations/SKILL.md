# Split Operations (Розщеплення операції)

## Що це і коли використовувати
Finmap дозволяє одну операцію (income/expense) розкласти на частки **АБО між кількома проектами, АБО між кількома категоріями**. Це для випадків типу:
- "Оплата 50000 за оренду — 30000 на проект А, 20000 на проект Б"
- "Витрата на корпоратив — 60% на категорію 'Командоутворення', 40% на 'Маркетинг'"

## Жорсткі правила Finmap

### Правило 1: projects-split XOR categories-split
Одна операція може бути розщеплена або по проектах, або по категоріях. **НЕ обома одночасно.** Якщо юзер просить розкласти і по тому і по тому — поясни обмеження і запропонуй вибрати один вимір.

### Правило 2: stake — це відсоток, сума має бути рівно 100
Поле `stake` вимірюється у відсотках. Сума всіх `stake` у масиві має бути **точно 100** (не 99.99, не 100.01).

### Правило 3: тільки `id` і `stake` — нічого більше
Backend сам обчислить `sum`, `companyCurrencySum`, `transactionSum` пропорційно. **Не передавай їх** — це джерело помилок (округлення може не зійтися).

### Правило 4: системні категорії розщеплювати не можна
Категорії типу "без категорії" (sentinels: `69e890516ba527a7d35ac320` для expense, `69e88d96901665a136d3df11` для income) не підтримують split. Якщо у списку часток є така — відхили операцію і скажи юзеру вибрати реальну категорію.

### Правило 5: НЕ передавай водночас `projectId`/`categoryId` і split-масив
- `projectId` (одиничне) — для звичайної не-розщепленої операції.
- `projects: [{id, stake}, ...]` — для розщепленої.
Якщо передаси обидва, Finmap може мовчки проігнорувати split або викинути помилку.

## Воркфлоу

### Крок 1. Зрозуміти що саме розщеплюємо
- Одна нова операція? → `mcp__finmap__create_operation` з split-масивом.
- Існуюча операція, яку треба розщепити? → `mcp__finmap__patch_operation` з split-масивом.

### Крок 2. Зібрати стейки
- Запитай юзера явно (або витягни з повідомлення) — у проектах це чи у категоріях.
- Перетвори у відсотки. Юзер може сказати "50/50" — це 50 і 50. Може сказати "третина-третина-третина" — округли до 33/33/34 або 33.33/33.33/33.34 (краще цілі числа).
- Перевір що сума = 100. Якщо ні — попроси юзера уточнити.

### Крок 3. Знайти ID
- Для проектів — `mcp__finmap__get_projects`, знайди за назвою. Якщо немає — `mcp__finmap__create_project`.
- Для категорій — `mcp__finmap__get_categories`, знайди. Якщо немає — `mcp__finmap__create_category`.
- Перевір, що жодна з категорій не sentinel "без категорії".

### Крок 4. Виконай виклик
**Приклад розщеплення 50/50 між проектами при оновленні операції:**
```
patch_operation({
  type: "expense",
  id: "<operation_id>",
  projects: [
    { "id": "<project_A_id>", "stake": 50 },
    { "id": "<project_B_id>", "stake": 50 }
  ]
})
```

**Приклад 70/30 між категоріями при створенні нової:**
```
create_operation({
  type: "expense",
  date: "2026-04-15",
  sum: 10000,
  accountFromId: "<account_id>",
  categories: [
    { "id": "<cat_A_id>", "stake": 70 },
    { "id": "<cat_B_id>", "stake": 30 }
  ]
})
```

### Крок 5. Підтверди юзеру
Покажи розклад:
> "Розщеплено операцію **10000 грн**: проект А — **50% (5000)**, проект Б — **50% (5000)**."

Суми тут показуєш для юзера — їх обчислив backend, ти не передавав.

## Як читати розщеплену операцію назад

Коли викликаєш `mcp__finmap__get_operations` і бачиш у результаті:
- `projects: [{id, stake, ...}]` з кількома елементами → це **розщеплена** по проектах
- `categories: [{id, stake, ...}]` з кількома елементами → **розщеплена** по категоріях
- Звичайне `projectId` / `categoryId` → не розщеплена

При презентації юзеру **завжди показуй розклад**, не пиши "проекти: A, B" — пиши "проекти: A (50%), B (50%)".

## Антипатерни

❌ **Стейки сумуються до 99 або 101** — Finmap відхилить виклик. Перевіряй.
❌ **Round trip через `sum`** — не передавай `sum` в split-обʼєктах, backend сам.
❌ **Split за двома вимірами одночасно** — не підтримується. Поясни юзеру.
❌ **Sentinel "без категорії" в split** — не підтримується. Запитай реальну категорію.
❌ **Передача `projectId` і `projects[]` в одному виклику** — поведінка непередбачувана.
