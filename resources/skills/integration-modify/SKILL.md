# Integration Modify (Зміна існуючої інтеграції)

## Чому окремий скіл — критичний баг
AI схильний на запит "поміняй щось в інтеграції" викликати `save_integration` замість `update_integration`. Це створює **другу інтеграцію з тим самим сервісом**, обидві крутяться у фоні паралельно — і ти отримуєш **дублікати операцій кожні 30 хвилин**. Цей скіл — захист від цього бага.

## Жорсткі правила

1. **НІКОЛИ не викликай `save_integration`** для модифікації. Він тільки для створення нової.
2. **ЗАВЖДИ починай з `list_integrations`** — без виключень.
3. **Передавай у `update_integration` тільки змінені поля**, інші не чіпай.

## Воркфлоу

### Крок 1. Знайти існуючу інтеграцію
Виклич `mcp__finmap__list_integrations({sessionId})`. Серед результатів знайди ту, про яку говорить юзер:
- За `serviceName` (якщо юзер сказав "Monobank-інтеграція")
- За `finmapAccountId` (якщо сказав "інтеграція на рахунок Карта-Привіт")
- Якщо неоднозначно — покажи юзеру список і спитай яка саме.

### Крок 2. Зрозуміти що міняти
Розпарси запит у конкретні поля:

| Юзер сказав | Поле, яке міняємо |
|--------------|-------------------|
| "поміняй інтервал на 10 хвилин" | `syncIntervalMin: 10` |
| "вимкни на час" | `enabled: false` |
| "увімкни знову" | `enabled: true` |
| "додай ще категорії в мапінг" | `syncPrompt: <full new prompt>` |
| "змінюй контрагента так і так" | `syncPrompt: <full new prompt>` |
| "поміняй ключ" | `serviceApiKey: <new key>` |
| "тепер на інший рахунок зачисляти" | `finmapAccountId: <new id>` |

### Крок 3. Якщо змінюється syncPrompt — формуй ПОВНИЙ новий

Це найтонший випадок. **Не намагайся склеїти старий syncPrompt з diff'ом** — пропусти важливе. Замість цього:
1. Прочитай поточний syncPrompt з `list_integrations` результату.
2. Зрозумій що саме треба додати/змінити.
3. Сформуй **повний новий** syncPrompt (як у `integration-setup` skill).
4. Покажи юзеру: "Ось як буде новий syncPrompt — все ОК?". Дай юзеру шанс перевірити.
5. Тільки після підтвердження — виклич `update_integration`.

### Крок 4. Виконати update
```
mcp__finmap__update_integration({
  id: "<integration id з list_integrations>",
  syncPrompt: "<тільки якщо міняли>",
  enabled: <тільки якщо міняли>,
  syncIntervalMin: <тільки якщо міняли>,
  ...
})
```

**Не передавай поля, які не міняються.** Це і є сенс update vs save.

### Крок 5. Підтвердження юзеру
Чітко скажи що змінилось:
> "Оновлено інтеграцію **{serviceName}**: інтервал тепер 10 хвилин."

або

> "Оновлено інтеграцію **{serviceName}**: тепер у мапінгу є категорія 'Підписки' для платежів з описом *netflix*, *spotify*, *apple*. Наступний автоматичний синк через {N} хв."

## Антипатерни

❌ **Виклик `save_integration` для зміни** → дублікат, синки накладаються.
❌ **Змінити syncPrompt не показавши юзеру** → юзер не помітить що щось пішло не так до першого зламаного синку.
❌ **Передавати всі поля у `update_integration`** → менш проблемно, але затирає поля, які могли бути оновлені іншим способом.
❌ **Питати "яку інтеграцію ти маєш на увазі"** перед `list_integrations` → витрачаєш повідомлення в нікуди, спочатку ОТРИМАЙ список, потім орієнтуйся.
