# Mass Import (Масовий імпорт операцій)

## Чому окремий скіл — три великих ризики
1. **Rate limit.** 50 створень підряд = 50+ викликів Claude. Без планування зʼїдає квоту юзера за один прийом.
2. **Дублікати.** Без дедуплікації імпорт двічі = 100 однакових операцій.
3. **Помилки в потоці.** Якщо третя операція впаде через невалідну дату — а перші дві вже створились — стан після помилки незрозумілий.

Цей скіл приписує процес, який мінімізує всі три.

## Воркфлоу

### Крок 1. Парсинг файлу
Файл уже передано тобі через Folio як текст (Excel/CSV/JSON/XML парсяться у файл-парсері до того як прийде до тебе). Витягни рядки з:
- Дата (нормалізуй у YYYY-MM-DD)
- Сума (signed: витрата −, дохід +)
- Опис/Контрагент
- (Опційно) Категорія, Проект, Тег
- (Опційно) Унікальний ID — для externalId

Якщо колонок не вистачає, або структура нечітка — **спочатку покажи юзеру** свою інтерпретацію колонок: "У файлі N рядків. Я розпізнав колонки: A→дата, B→сума, C→опис. Так правильно?".

### Крок 2. Превʼю + угрупування
**Не показуй юзеру всі 50 рядків.** Замість цього:
1. Перерахуй: "У файлі **{N}** операцій на загальну суму **{X}** грн".
2. Згрупуй по контрагенту/категорії і покажи топ-5 груп:
   > "За контрагентами:
   > - АТБ — 12 операцій, 8 740 грн
   > - ОККО — 5 операцій, 5 200 грн
   > - Сільпо — 4 операції, 3 100 грн
   > - інші — 8 операцій, 4 500 грн"
3. Покажи перші 3 і останні 2 операції як preview.
4. Запитай: "Все правильно? Імпортуємо?"

Це дає юзеру інтуїцію за 5 секунд замість прокручування 50 рядків.

### Крок 3. Підготовка до імпорту
Перед першим `create_operation`:

1. **Знайти/створити рахунок.** Якщо юзер не сказав явно на який рахунок — питай.
2. **Знайти/створити контрагентів масово.** Унікальні назви з файлу → перевір через `get_counterparties` → створюй відсутні. Зроби це **до** циклу імпорту, а не всередині.
3. **Знайти/створити категорії масово.** Те ж саме.
4. **Дедуплікація — один батч-виклик.** Збери всі expected externalIds і виклич `mcp__finmap__check_externalIds({externalIds, accountIds, startDate, endDate})` ОДИН раз. Усі чотири параметри ОБОВʼЯЗКОВІ: externalIds — список айдішників, accountIds — той рахунок куди імпортуєш, startDate/endDate — період який покриває дати у файлі. Інструмент зробить один list-виклик у Finmap і поверне `{existing, missing, scannedOps, totalInWindow}` — створюй тільки ті, що в `missing`. Якщо у відповіді є `warning` — період надто широкий, звузь і виклич ще раз. **НЕ викликай `get_operations({search: externalId})`** — search не шукає по externalId полю.

### Крок 4. Дедуплікація — externalId formatи

Якщо файл з банку чи зовнішнього сервісу — використовуй `externalId = "{source}_{rowId}"` де `source` — назва джерела (наприклад "import-2026-04-15-csv"), `rowId` — стабільний ідентифікатор з файлу (номер транзакції банку, або хеш дата+сума+опис).

**Якщо стабільного ID нема** (просто Excel від юзера) — генеруй детермінований хеш:
```
externalId = "manualImport_" + md5(date + amount + description).substring(0,12)
```

Це дозволить юзеру повторно імпортувати той самий файл без дублікатів.

### Крок 5. Імпорт пакетами

**Не запускай 50 викликів `create_operation` підряд** — це rate-limit-вбивство.

Імпортуй блоками по 10 з прогрес-індикатором:
> "Імпортую пакет 1/5 (операції 1-10)..."

Після кожного пакета:
- Скажи скільки створено / пропущено (бо дублікат) / помилка.
- Якщо помилка > 1 в пакеті — **зупинись** і спитай юзера що робити.

### Крок 6. Підсумок
Коли все завершилось:
> "Імпорт завершено:
> - ✅ Створено: **42** операції
> - 🔁 Пропущено (дублікати): **6**
> - ❌ Помилки: **2** (рядки 23 і 47 — невалідна дата)
>
> Загальна сума створених: **47 200 грн**."

Це дає юзеру повну картину без сюрпризів.

## Що з підтвердженням mutation

Кожен `create_operation` — це mutation, яка викликає твій підтверджувальний UI. Для масового імпорту це проблема: 50 модальних вікон.

**Рішення:** ПЕРЕД першим створенням питай юзера: "Імпорт створить **N** операцій. Хочеш підтверджувати кожну окремо чи дозволити всі за раз?". Якщо "за раз" — юзер сам у Folio увімкне auto-approve для сесії або скаже тобі один раз "так, імпортуй усі без перепиту".

Якщо юзер хоче по одному — приймай це. Серйозний бухгалтер може хотіти переглянути кожну.

## Інтеграція з reconcile-statement

Часто mass-import — це наступний крок після `reconcile-statement` skill: юзер звірив виписку, побачив "❌ Бракує у Finmap: 12 операцій", погодився імпортувати. У такому випадку:
- Дані вже структуровані (вийшли з reconcile як `missingInFinmap`).
- Дедуплікація вже зроблена матчером.
- Просто проведи через Крок 5-6 цього скіла.

## Антипатерни

❌ **50 окремих `create_operation` без батчингу** → rate limit.

❌ **Перевірка дубликатів у циклі** (по одному виклику get_operations на кожен рядок) → 50 зайвих API-викликів.

❌ **Створення категорій/контрагентів у циклі імпорту** → знов зайві виклики.

❌ **"Тихий" імпорт без превʼю** → юзер не розуміє що ти додав, і потім видаляє все.

❌ **Без external Id** → повторний імпорт того ж файлу = дублікати.
