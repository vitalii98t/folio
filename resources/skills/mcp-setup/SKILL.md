# MCP Setup (універсальне підключення сервісів через MCP)

## Що ти робиш
Знаходиш в інтернеті MCP-сервер для сервісу, який юзер хоче підключити, читаєш його документацію, питаєш у юзера потрібні токени і креденшелі (з інструкцією як їх отримати), реєструєш сервер у Folio через `add_mcp_server`. Після цього Claude (тобто ти) отримуєш доступ до інструментів того сервісу — від наступного повідомлення.

## ⚡ Folio постачає runtime'и з коробки

**Не попереджай юзера про встановлення `uv`, `uvx`, `node`, `npm`, `npx` — Folio bundled їх усі.** Коли реєструєш сервер з командою `npx`, `uvx` або `node`, не пиши "переконайся що в тебе встановлений [runtime]", "if you get command not found — install via...", "передумова — встанови uv" тощо. Це **застаріла порада** яка плутає юзера. Команди резолвяться у наші bundled бінарники автоматично.

Якщо сервер потребує **щось інше** (наприклад `deno`, `bun`, або кастомний бінарник з GitHub Releases) — тоді так, попередь юзера. Але для uv-/node-серверів — ні.

## Воркфлоу

### Крок 1. Підтвердити що саме потрібно
Якщо юзер сказав узагальнено ("хочу інтеграцію зі своїм CRM"), спитай назву конкретного сервісу. Якщо назвав явно ("Telegram", "Notion") — переходь до Кроку 2.

### Крок 2. Перевір чи такий сервер уже є
Виклич `mcp__finmap__list_mcp_servers`. Якщо у списку вже є запис з відповідною назвою — скажи юзеру: *"Сервер `<name>` вже підключений. Хочеш переналаштувати або заміни?"*. Не створюй дублікати.

### Крок 3. Знайти офіційний/найкращий MCP-сервер
Шукай у такому порядку:

1. **WebSearch:** запит `"<service-name> MCP server github"` або `"modelcontextprotocol <service-name>"`
2. Дивись пріоритетно:
   - **Офіційний:** `github.com/modelcontextprotocol/servers` (Slack, GitHub, Postgres, Google Drive, Filesystem, Puppeteer, Brave Search тощо)
   - **Спільнота з зірками:** найбільш популярний open-source проект з MCP-сервером
   - **Анонсований офіційно** компанією-власником сервіса
3. Вибирай:
   - Активна підтримка (commits за останній місяць)
   - Чіткий README з інструкцією встановлення
   - `npx -y @package/name` або `uvx package-name` форма запуску (без зайвих setup-кроків)

**Якщо не знайшов** офіційного — скажи юзеру: *"Не знайшов офіційного MCP-сервера для `<service>`. Можеш дати посилання на репо, який ти знайшов?"*. Тоді переходь до Кроку 4 з URL юзера.

### Крок 4. Прочитати README сервера
**WebFetch** на репозиторій (file README.md або сторінка GitHub):

```
WebFetch("https://github.com/<owner>/<repo>/blob/main/README.md")
```

Витягни:
- **Команду запуску** (зазвичай у секції *Installation*, *Quick start*, *Usage*)
- **Список env-перемінних** з назвами (типу `SLACK_BOT_TOKEN`)
- **Як отримати кожен токен** — посилання у документації або у dev-консолі сервіса
- **Список доступних інструментів** (щоб юзер зрозумів що зможе робити)

### Крок 5. Зведення для юзера
Покажи **компактну** таблицю того що знайшов:

```markdown
✅ Знайшов MCP-сервер для **Telegram**: [<repo-name>](<repo-url>)

📦 **Команда запуску:** `npx -y @modelcontextprotocol/server-telegram`

🔑 **Потрібні токени:**
- `TELEGRAM_BOT_TOKEN` — отримай через @BotFather у Telegram:
  1. Відкрий https://t.me/BotFather
  2. Команда `/newbot` → задай імʼя та username
  3. Скопіюй токен типу `1234567890:ABCdef...`

🛠️ **Що ти зможеш робити:**
- Надсилати повідомлення в чати, де є бот
- Читати повідомлення з груп
- Створювати polls, надсилати файли
- (повний список у `<repo>/README.md`)

Скинь мені токен, і я налаштую все автоматично.
```

### Крок 6. Отримати токен від юзера
Чекай на відповідь з токеном. Якщо юзер питає "як саме отримати" — деталізуй конкретні крокі з README.

### Крок 7. Зберегти конфіг (через add_mcp_server)
Виклич `mcp__finmap__add_mcp_server`. Це **mutation** — юзер побачить підтверджувальну плашку з повним конфігом.

```javascript
add_mcp_server({
  name: "telegram",                              // короткий namespace
  command: "npx",
  args: ["-y", "@modelcontextprotocol/server-telegram"],
  env: {
    "TELEGRAM_BOT_TOKEN": "<token від юзера>"
  },
  autoApproveAll: false,                          // безпечно за замовчуванням
})
```

### Крок 8. Підтвердження
Після успіху скажи юзеру:

```
✅ Сервер **telegram** підключений.

⚠️ **Він активується з наступного повідомлення** — у цьому повідомленні я ще не маю доступу до його інструментів.

У наступному повідомленні можеш просити, наприклад:
- *"Надішли в чат @myteam повідомлення про новий звіт"*
- *"Які повідомлення були в #general за сьогодні"*
- *"Створи poll з варіантами A/B/C"*
```

## Жорсткі правила

1. **Завжди WebFetch на README перед налаштуванням** — не вгадуй конфіг з памʼяті.
2. **Завжди list_mcp_servers перед add_mcp_server** — щоб не дублювати.
3. **Токени тільки через `env`**, ніколи через `args` (у args вони видимі у логах процесу).
4. **`autoApproveAll: false` за замовчуванням** — безпека > зручність. Юзер сам увімкне якщо захоче.
5. **Пояснюй юзеру звідки взяти токени** — не залишай в стилі "ти знаєш як".
6. **Один токен → один сервер** — не пропонуй два аналогічних варіанти за раз.

## Як шукати рідкісні сервіси

Якщо WebSearch не знаходить результат на перші 1-2 запити:

1. Спробуй `"<service-name> mcp claude integration"`
2. Перевір awesome-list: WebFetch `"https://github.com/punkpeye/awesome-mcp-servers"` — там великий каталог
3. Якщо сервіс має офіційне API але немає MCP-сервера — **запропонуй юзеру скіл `integration-setup`** (через generic `http_request` + Folio-інтеграція)

## 📦 Готові рецепти для популярних сервісів

Для деяких сервісів конфіг **уже відомий і перевірений** — не шукай у WebSearch, не давай юзеру вибір "тільки читати чи повний доступ". Просто виконуй рецепт нижче.

### Google Sheets

**Завжди йди повним шляхом** через `xing5/mcp-google-sheets` + Service Account.
НЕ пропонуй "просто кинь URL — я прочитаю через gdrive-tool" як альтернативу — бо хоч `gdrive_get_file_content` і вміє читати Sheets через CSV-експорт, цей MCP-сервер дає read **та** write з 19 інструментами одразу. Один шлях, єдина точка налаштування.

НЕ пропонуй `/mcp` claude.ai Google Drive — це працює тільки у Claude Code TUI, не у Folio чаті.

**Інструкція юзеру (один раз, ~5 хв):**

```
🟢 Налаштування Google Sheets — крок за кроком:

1. https://console.cloud.google.com → створи (або обери існуючий) проект
2. APIs & Services → Library → увімкни:
   • Google Sheets API
   • Google Drive API
3. IAM & Admin → Service Accounts → Create Service Account
   • Name: "folio-sheets" (або будь-яке)
   • Role: Editor
   • Done
4. У створеному SA → ⋮ (три точки) → Manage keys → Add Key → JSON
   → браузер скачає файл типу <project>-<id>.json
5. Скопіюй email Service Account'у (виглядає як folio-sheets@<project>.iam.gserviceaccount.com)
6. У Google Sheets відкрий конкретну таблицю з якою хочеш працювати →
   правий верхній кут Share → встав email Service Account'у → роль: Editor → Send
   (Якщо плануєш працювати з кількома таблицями — поділись з кожною з тим самим SA email.)

Коли готово — скинь мені у чат:
• **Вміст JSON-файла** (відкрий файл текстовим редактором, скопіюй усе від { до } і встав сюди). Я збережу локально у безпечному місці Folio.
• (Опційно — на потім) посилання на таблиці з якими плануєш працювати — щоб одразу їх перевірити.
```

**ВАЖЛИВО про прийом JSON:** коли юзер скине вміст JSON, ти **не цитуй його у відповіді** і не "ехо" назад — це credential. Просто збережи через тул і скажи "✅ збережено".

**Виклик послідовності після того, як юзер дав JSON:**

Крок 1: збережи credential у Folio-credentials-dir:
```
save_service_account_key({
  jsonContent: "<повний JSON що дав юзер>",
  label: "gsheets"
})
→ повертає { path: "C:\\...\\credentials\\gsheets-abc12345.json", email: "folio-sheets@..." }
```

Крок 2: створи MCP-сервер з шляхом який повернув save_service_account_key:
```
add_mcp_server({
  name: "gsheets",
  command: "uvx",
  args: ["mcp-google-sheets@latest"],
  env: {
    "SERVICE_ACCOUNT_PATH": "<path returned by save_service_account_key>"
  },
  autoApproveAll: false
})
```

**Не передавай `DRIVE_FOLDER_ID`** — Sheets MCP без нього працює з **будь-якою таблицею**, яку Service Account має право бачити (тобто з тими, які юзер явно поділив на Кроці 6). Якщо юзер захоче зашити "робочу папку" як дефолт для нових таблиць — це окрема настройка пізніше, не для базового сетапу.

**Підтвердження юзеру після успіху:**

> ✅ Сервер `gsheets` підключений (Service Account: `folio-sheets@<project>.iam.gserviceaccount.com`). Активується з наступного повідомлення. Можу: створювати нові таблиці, читати дані/формули, оновлювати клітинки, додавати рядки, будувати графіки.
> 
> Працюю з будь-якою таблицею, яку ти поділиш з цим SA email. Просто кидай мені посилання на потрібну таблицю в наступних запитах — я її бачитиму.

### Google Drive (для імпорту файлів)

**НЕ пропонуй** ставити окремий MCP-сервер для Drive — у Folio вже є **нативний UI-wizard** для авто-імпорту з Drive папок. Він використовує API key (не Service Account), що простіше.

Якщо юзер каже "хочу імпорт з Google Drive папки" → активуй замість цього скіл `folder-import-setup` (він направить у Settings → "+Авто-імпорт з папок").

### Інші Google-сервіси (Gmail, Calendar, Docs окремо)

Поки немає bundled рецепту — використовуй стандартний flow з WebSearch і чекай документації від юзера.

## Антипатерни

❌ **Вгадати npx-команду** не читаючи README — половина шансу що неправильно
❌ **Зберегти токен у `args`** — це безпекова дірка
❌ **`autoApproveAll: true`** за замовчуванням — юзер не встиг подумати
❌ **Дубльований сервер** з тим самим `name` — два процеси з'їдатимуть ресурс і колидитимуть інструменти
❌ **Питати у юзера команду npx** — це твоя робота прочитати README і знайти
